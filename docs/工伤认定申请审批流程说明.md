# 工伤认定申请审批流程说明

## 1. 核心规则

- 一个安全生产事故对应一个审批流程。
- 一个事故可以包含多张工伤认定申请表，所有申请表统一随事故提交审批。
- 没有工伤认定申请表的事故不进入审批流程。
- 主管部门负责人为并行抄送节点，不影响主流程流转。

## 2. 流程节点

```text
发起单位提交
    ↓
安全环保部审批
    ├─→ 主管部门负责人抄送（并行、非阻塞）
    ↓
人力资源部部长审批
    ↓ 选择工伤保险办理人员
工伤保险办理人员签收
    ↓
结束
```

### 节点规则明细

| 节点 | 办理角色/人员 | 人员匹配规则 | 主要操作 | 流转规则 |
|---|---|---|---|---|
| 1. 发起单位提交 | 发起单位中拥有本菜单权限的人员 | 通过菜单权限控制，不额外限制“安全员及以上”身份 | 填写事故概况和全部工伤认定申请表，发起审批 | 所有申请表填写完成后，提交至安全环保部审批 |
| 2. 安全环保部审批 | 安全环保部审批角色人员 | 由安全环保部角色配置办理人，不允许发起人自由指定 | 查看事故及申请表，审批通过、退回或驳回 | 通过后同时触发节点3抄送和节点4人力资源部审批 |
| 3. 主管部门负责人抄送 | 发起单位对应主管部门的部门负责人/部长 | 根据事故发起单位匹配对应主管部门，再从该部门负责人角色中获取人员 | 接收查看抄送信息，可确认或不确认 | 非阻塞节点，不等待确认，不影响人力资源部审批和后续主流程 |
| 4. 人力资源部部长审批 | 人力资源部部门负责人/部长 | 从人力资源部的部门负责人角色中匹配部长 | 审核事故及申请表，审批通过时选择工伤保险办理人员 | 选择办理人员后，流转至节点5 |
| 5. 工伤保险办理人员签收 | 人力资源部工伤保险办理人员 | 仅允许使用人力资源部已配置的工伤保险办理人员，不允许任意选人 | 查看申请内容并进行签收 | 签收完成后流程结束 |
| 6. 结束 | 无 | 系统自动结束 | 查看流程结果 | 无后续节点 |

### 角色配置要求

- 发起单位提交：配置菜单权限即可，不通过角色身份做额外拦截。
- 安全环保部审批：配置“安全环保部审批”角色及对应办理人员。
- 主管部门抄送：维护各发起单位与主管部门的对应关系，并配置主管部门负责人/部长。
- 人力资源部审批：配置人力资源部部门负责人/部长。
- 工伤保险办理：配置人力资源部工伤保险办理人员清单，供部长审批时选择。

流程以事故为主对象保存，申请表是事故流程下的明细内容；不能为同一事故下的单张申请表单独发起流程。

## 3. 页面交互

### 事故记录列表

“工伤申请”状态显示四种状态：

- 无工伤申请
- 待发起审批
- 审批中
- 已结束

没有申请表时显示“无工伤申请”，不提供流程操作。

### 事故详情页

- 所有申请表填写完成后，页面右上角显示“发起审批”。
- 流程发起后，右上角显示当前节点的“审批”按钮。
- 点击审批后打开审批弹窗，确认提交时需要二次确认。
- 人力资源部部长审批时，必须选择工伤保险办理人员。
- 审批完成后进入下一节点，签收完成后流程结束。

## 4. 关键数据字段

```js
workflowStatus     // 未发起、审批中、已结束
currentNode        // 当前办理节点
ccStatus           // 主管部门抄送状态
hrStatus           // 人力资源部审批状态
insuranceHandler   // 工伤保险办理人员
```

当前原型使用 Mock 数据实现，不调用后台接口。正式开发时需将流程状态、办理人和审批记录改为后端数据，并按权限返回可操作节点。
